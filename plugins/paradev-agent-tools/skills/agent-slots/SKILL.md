# Слоты

В начале новой задачи сначала выполни `paradev-agent status --json`. Сессия остаётся в рабочей копии запуска:
main — в main, слот — в текущем слоте. При `slot: null` продолжай в текущей копии по правилам проекта,
не выделяй слот и не переходи в другой worktree автоматически. Workspace main и Git-ветка main/master —
разные вещи: ветку задачи в основной копии готовь по правилам проекта. Занятость или конфликт —
повод спросить пользователя, а не переехать без поручения.
В общем режиме Paradev Host Service резервирует выбранный слот при открытии чата.
На старых версиях доверенный хук Codex `UserPromptSubmit` проверяет принадлежность слота
перед началом хода. Первое сообщение в свободном слоте сразу получает модель. Следуй правилам
проекта, чтобы определить, нужно ли получать задачу или создавать ветку перед работой.
При занятом слоте или конфликте сначала реши, где продолжить.
[Общий режим и резервный хук](../../docs/cli.md#резерв-и-освобождение-в-paradev-host-service).

Когда процесс проекта требует подготовить слот до запуска исполнителя, используй
`paradev-agent slot prepare <workspace-id> --branch B --task KEY [--from BASE]`.
Тип, имя ветки и базу определи по проекту (SberCRM — `work task-meta <KEY>`). При грязных изменениях,
живой сессии или неясной принадлежности остановись и спроси пользователя. Обычный prepare сохраняет
защиту живых сессий. При успешном prepare повтори status и проверь ветку и имя `slot-N · KEY`.

Слоты — для отдельных задач, порученных пользователем или оркестратором. Для ревью своей работы
используй встроенного субагента в той же копии; отдельная сессия — только по прямой просьбе человека,
по [agent-orchestrate](../agent-orchestrate/SKILL.md).
Каждой дополнительной сессии исполнителя отдельной задачи выдели свой слот: `slot take`, затем `create`
с возвращённым workspace id. Не создавай для этого worktree или workspace вручную и не запускай
исполнителя в основной копии с указанием перейти в другую папку. Одна ветка занимает один слот.
Если проект явно предписывает иной механизм изоляции, разреши конфликт инструкций до создания.

```sh
paradev-agent slot ls --project <project> --json
paradev-agent slot take --project <project> --branch <branch> --task <task> --dry-run
paradev-agent slot take --project <project> --branch <branch> --task <task> --json
paradev-agent close --workspace <workspace-id>
```

Сохрани `workspace` и `path` из ответа take. Он использует свободный слот либо создаёт новый,
затем подготавливает ветку. Для команд slot указывай проект, чтобы одинаковые slot-N не перепутались;
для `create --workspace` передавай id. Реальную ветку проверяй Git: колонка Superset может устареть.

Находясь в слоте, можно без имени: `paradev-agent close`, `paradev-agent slot sync-back [--apply]`,
`paradev-agent slot sync [--apply]`. Workspace определяется по `SUPERSET_WORKSPACE_ID`, иначе по cwd,
включая подкаталоги/симлинки. Здесь `--project` необязателен; если указан, должен совпадать.
Неоднозначность, устаревший ID окружения и основная копия — отказ, не подбирай другой слот.
`close` сохраняет проверки занятости и правила release проекта; синхронизация без `--apply` — план.
Для сводки текущего контекста используй `paradev-agent status --json`: ветка и изменения берутся из Git,
при нескольких сессиях возвращается список, а не произвольная «текущая».

База — `--from`, иначе `slot.mainBranch` из `.agent-cli.json`, иначе `origin/HEAD`.
Перед созданием новой ветки CLI обязательно обновляет удалённые ветки через fetch с prune,
включая путь с проектной командой `slot.take`. Новая ветка начинается от полученного SHA
`origin/<base>`, а не от локального master/main или прежнего HEAD слота. JSON подготовки содержит
`from`, `base` (SHA) и `fetched`; после создания проверяется, что ветка содержит эту базу.
Существующая сохраняет свою историю и обновляется fast-forward от своей удалённой ветки;
ошибка обновления останавливает подготовку. Удалённая на сервере ветка не восстанавливается из кеша.
Не требуй совпадения HEAD с базой у существующей ветки. Отставание от базы — отчёт, не разрешение merge.
Если fetch упал, не переходи на старую базу: `--offline` допускается по явному выбору пользователя.

Свободный слот называется ровно slot-N, чист, без живых сессий и невлитых коммитов. Выбор идёт по номеру.
`take` пропускает занятые/грязные/невлитые и может создать новый — если слоты копятся, покажи причины.
`prepare` грязного слота делает бэкап и останавливается; `release` грязного отказывает.
Код 9 не обходи автоматически через `--carry`, `--allow-unmerged` или ручное переключение ветки.
Основную копию CLI не переключает. При автоподготовке хук допускает только свой чат, подтверждённый по точным ID.

Без конфигурации prepare копирует зависимости из основной копии (включая npm workspaces),
устанавливает их по lock-файлу при необходимости и настраивает хуки. Не повторяй установку вручную
без причины. Если задан `slot.take` / `slot.release`, CLI вызывает команду проекта вместо встроенной.
Для `slot.take` fetch выполняется до команды, проверка ветки — после неё, до отметки слота готовым.
Команда, создавшая ветку от старой базы или не обновившая существующую ветку, даёт ошибку;
результат остаётся на диске для разбора, автоматически ветку не сбрасывай.
Проверки готовности и завершение задачи выполняй по скиллам продукта.

`paradev-agent close` сохраняет ветку задачи, переводит чистый слот в detached HEAD и проверяет release.
Одного переименования workspace недостаточно для отчёта об освобождении.

## Локальные файлы

`slot.localFiles` берётся из конфига основной копии, если он есть. Это копии gitignored-файлов,
не ссылки. prepare переносит слот → основная → слот; release внутри close/gc — слот → основная.
Markdown сливается по разделам; код 9 означает конфликт. Покажи конфликтующие пути, не перетирай их.

```sh
paradev-agent slot sync-back <slot> --project <project>
paradev-agent slot sync-back <slot> --project <project> --apply
paradev-agent slot sync <slot> --project <project> --apply
```

Без `--apply` это план. Следуй правилам проекта об одобрении переноса; не заменяй CLI ручным копированием.
Подробности и конфигурация — [руководство по CLI](../../docs/cli.md#слоты).

Завершение — `paradev-agent close` по [agent-cleanup](../agent-cleanup/SKILL.md): история для resume,
закрытие сессии, один штатный release и проверка свободного слота. Отдельный slot release не нужен.
Если сессия уже исчезла, вызови close из пустого слота или явно --workspace W. Грязную копию не очищай
и live-защиту не обходи. Старый slot release оставлен только как совместимый вход в close.
