# agent-cli

Личный CLI для сессий Codex/Claude в Superset, worktree-слотов и коммитов по плану.
Go 1.26+. Проверки `go test ./...` и `go vet ./...`.

## Источники инструкций

- [README](README.md) — обычный путь работы, ограничения, устройство и конфигурация.
- [Справочник команд](docs/commands.md) — все команды и флаги; в CLI — `agent <группа> --help`.
- [Встроенные скиллы](docs/skills.md) — процессы для агентов. Открыть: `paradev-agent --help <тема>`.
- `examples/agent-cli/SKILL.md` — устанавливаемый роутер; личный `references/personal.md`
  рядом с установленным роутером сохраняется установщиком и в пакет не копируется.

При работе над самим CLI изучи фактический diff и подходящие тесты.
При использовании CLI в другом проекте сначала читай его инструкции: этот AGENTS.md описывает
пакет и не заменяет процесс, проверки, формат коммитов или разрешения продуктового проекта.
Не меняй CLI ради обхода ограничений чужого проекта.

## Обязательные ограничения

- CLI никогда не выполняет `git push`. Коммиты — только в пределах поручения пользователя.
- `paradev-agent commit` без `--apply` — план. Состав коммита — точные файлы/ханки; чужой индекс
  не очищать и в коммит не включать. Правила сообщения и путей — из `.agent-cli.json`.
- Основную копию проекта не переключать. Грязные файлы, невлитые ветки и живые/ожидающие сессии
  не удалять и не обходить их защиты автоматически через force/carry/allow-unmerged.
- Операции связывать с точными session/workspace IDs. Соседние чаты не закрывать ради уборки.
- Для штатного завершения — `paradev-agent close` по [agent-cleanup](skills/agent-cleanup/SKILL.md).
  Сначала согласованные действия и сохранение итога; затем receipt в финальном ответе.
  `queued` не означает `completed`; имя slot-N после close/gc не означает освобождения Git.
- Один шаг release выполняется один раз: через настроенный hook проекта либо штатный механизм.
  Постоянного watcher/демона для закрытия нет: close использует общий короткоживущий worker.
- Перенос локальных файлов — через механизм `slot.localFiles`, с сохранением конфликтующих
  версий и бэкапами. Конфликт не перетирать вручную ради успешного завершения.

После изменений запускай подходящие тесты. Живые чужие сессии не используй для разрушающих тестов.
Команды, схемы JSON, коды выхода и подробные процессы поддерживай в README/справочнике/скиллах,
не копируй их сюда второй раз.
