# Коммит по плану

Прочитай правила коммита и проверок текущего проекта, затем проверь diff и статус.
CLI управляет составом коммита; он не заменяет процесс продукта и не выбирает формат сообщения.
Используй его при запросе коммита по плану или необходимости выбрать отдельные ханки.

```sh
agent commit hunks <file>
agent commit plan.json
agent commit plan.json --apply
```

План — массив элементов. Каждый коммит содержит `message` и точные `paths` и/или `hunks`:

```json
[
  {
    "message": "fix: сообщение по правилам проекта",
    "paths": ["src/example.js"],
    "hunks": [{ "path": "README.md", "include": [1, 3] }]
  }
]
```

Каталоги в paths запрещены. Номера include получай из `hunks` на текущем diff;
после изменения файла пересмотри выбор. Вместо номеров допускается строка-маркер.
Проверь ограничения `.agent-cli.json`: `forbiddenPaths`, `messagePattern`, `trailerPattern`, `closeCommand`.
Не копируй трейлеры из примера README, если проект требует другой формат.

Сухой прогон использует временный индекс и не меняет HEAD или основной индекс.
Покажи конкретный состав и сообщения; `--apply` выполняй только по отмашке пользователя на коммит.
Чужие staged-файлы не включаются; staged-файл самого плана вызывает отказ.
Не очищай чужой индекс ради прохождения проверки. CLI защищает от параллельного изменения HEAD.

`{"closeChange": "task"}` запускает настроенный `closeCommand` и создаёт отдельный коммит закрытия.
Добавляй этот элемент только по процессу проекта и при разрешённом закрытии задачи.
После выполнения проверь итоговые коммиты и статус. Push CLI не делает.
Полная схема — [руководство по CLI](../../docs/cli.md#формат-плана-agent-commit).
