# Слоты

Каждой дополнительной сессии исполнителя выдели свой слот: `slot take`, затем `sess create`
с возвращённым workspace id. Не создавай для этого worktree или workspace вручную и не запускай
исполнителя в основной копии с указанием перейти в другую папку. Одна ветка занимает один слот.
Если проект явно предписывает иной механизм изоляции, разреши конфликт инструкций до создания.

```sh
agent slot ls --project <project> --json
agent slot take --project <project> --branch <branch> --task <task> --dry-run
agent slot take --project <project> --branch <branch> --task <task> --json
agent slot release <slot> --project <project>
```

Сохрани `workspace` и `path` из ответа take. Он использует свободный слот либо создаёт новый,
затем подготавливает ветку. Для команд slot указывай проект, чтобы одинаковые slot-N не перепутались;
для `sess create --workspace` передавай id. Реальную ветку проверяй Git: колонка Superset может устареть.

База — `--from`, иначе `slot.mainBranch` из `.agent-cli.json`, иначе `origin/HEAD`.
Новая ветка начинается от свежего `origin/<base>`; существующая сохраняет свою историю.
Не требуй совпадения HEAD с базой у существующей ветки. Отставание от базы — отчёт, не разрешение merge.
Если fetch упал, не переходи на старую базу: `--offline` допускается по явному выбору пользователя.

Свободный слот называется ровно slot-N, чист, без живых сессий и без невлитой ветки.
`take` пропускает занятые/грязные/невлитые и может создать новый — если слоты копятся, покажи причины.
`prepare` грязного слота делает бэкап и останавливается; `release` грязного отказывает.
Код 9 не обходи автоматически через `--carry`, `--allow-unmerged` или ручное переключение ветки.
Основную копию и слот с живой сессией CLI не переключает.

Без конфигурации prepare копирует зависимости из основной копии (включая npm workspaces),
устанавливает их по lock-файлу при необходимости и настраивает хуки. Не повторяй установку вручную
без причины. Если задан `slot.take` / `slot.release`, CLI вызывает команду проекта вместо встроенной.
Проверки готовности и завершение задачи выполняй по скиллам продукта.

`release` оставляет ветку и переводит чистый слот в detached HEAD на свежей базе.
Возврат имени slot-N после закрытия сессии ещё не означает, что ветка влита или слот освобождён.

## Локальные файлы

`slot.localFiles` берётся из конфига основной копии, если он есть. Это копии gitignored-файлов,
не ссылки. prepare переносит слот → основная → слот; release и возврат имени после close/gc — слот → основная.
Markdown сливается по разделам; код 9 означает конфликт. Покажи конфликтующие пути, не перетирай их.

```sh
agent slot sync-back <slot> --project <project>
agent slot sync-back <slot> --project <project> --apply
agent slot sync <slot> --project <project> --apply
```

Без `--apply` это план. Следуй правилам проекта об одобрении переноса; не заменяй CLI ручным копированием.
Подробности и конфигурация — [README](../../README.md#слоты).
