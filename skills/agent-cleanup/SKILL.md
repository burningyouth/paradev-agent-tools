# Завершение и уборка

Одна операция завершения — `agent close`: сохранить историю для resume, закрыть сессию,
выполнить release проекта и проверить, что слот действительно свободен. Заметка сама по себе
и имя slot-N не означают успеха. Грязная копия, другая сессия или ошибка release — блокер.
В основной копии слота нет: закрывается только сессия, release отмечается not-applicable.

```sh
agent close task-x --note "Сделано; следующий шаг" --json
agent close --summary-file /absolute/outcome.md --json
agent close --workspace W --dry-run --json
agent close --result /absolute/result.json --json
```

Сначала заверши согласованные действия по продукту. Коммиты и внешние действия — только в пределах
поручения. Итог необязателен как файл: без --note/--summary-file CLI сохраняет последний ответ.
Если файл нужен, храни его вне слота, например в ~/.agent-cli/reports/.
Для собственного chat в слоте вызови close последним действием; в финальный ответ включи итог,
resultFile и буквальный receipt из JSON. Worker ждёт подтверждённого финального ответа без новых
сообщений/approvals и затем закрывает chat и освобождает слот. Не жди worker в том же чате.
Терминальное самозакрытие выполняет отдельный worker после выхода вызывающего CLI.

Queued — очередь, только completed — проверенное завершение. При ошибке прочитай resultFile
и фактическое состояние. Не обходи защиту dirty/live/UUID и не повторяй release hook вслепую.
Уже detached-слот через hook повторно не отпускается. Ветка задачи остаётся для resume.
Если сессия исчезла после сбоя, close из пустого слота или по сохранённому алиасу доводит release
до конца. --workspace явно выбирает пустой workspace. Соседние чаты не закрывай.
Старые finish и slot release — только совместимые входы в close; отдельно их не вызывай.

При подключённых `agent hook install` события SessionStart/Stop сохраняют назначение и заметку,
SessionEnd автоматически доводит release после фактического выхода. Результат — end-jobs в agentHome;
грязный/занятый/переназначенный слот остаётся с блокером и уведомлением. Stop, clear и субагенты
release не запускают. Аварийное закрытие может не доставить hook: тогда используй обычный close.
Новые определения Codex требуют доверия через /hooks; установщик его не подменяет.

## Массовая уборка

```sh
agent ls --json
agent gc --project P --json
agent gc --project P --apply --json
```

Без --apply — план. Применяй в пределах поручения пользователя и правил проекта.
Gc использует тот же close и release; грязный слот или несколько сессий оставляет с причиной.
Не закрывает работающие, ожидающие ответа/разрешения, с вопросом в последнем ответе, keep и текущую
сессию; без доступного журнала состояние не угадывает. Лимит и RAM не разрешают обходить защиты.
`agent keep <alias>` исключает сессию из gc; `agent keep --rm <alias>` снимает пометку.
Pen закрывается через idle-check; --keep-pen сохраняет его. При ручной работе — [agent-pen](../agent-pen/SKILL.md).

История — `agent log`; продолжение — `agent resume`. Процесс — [agent-sessions](../agent-sessions/SKILL.md).
