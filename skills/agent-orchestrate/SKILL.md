# Работа с исполнителями

Применяй, когда пользователь поручил делегирование или параллельную работу. Выдели независимые задачи
и обозначь зависимости. Для каждой запиши результат, границы изменений и проверки по текущему проекту.
Учитывай общий лимит сессий из `agent sess ls --json`; не создавай лишних исполнителей ради количества.

Запуск исполнителя выполняет оркестратор. Для каждого исполнителя подготовь отдельный слот по [agent-slots](../agent-slots/SKILL.md), затем создай
сессию по [agent-sessions](../agent-sessions/SKILL.md). Рабочие копии создаёт agent CLI;
другие инструменты Superset могут использоваться для раскладки панелей, но не для обхода слотов.
Перед `sess create` сам проверь фактическую ветку Git, имя слота, чистоту и отсутствие живых сессий
в выделенной копии. Запускай `agent sess create --workspace W --branch B --task KEY --prompt-file F`:
CLI повторит проверки под блокировкой и передаст исполнителю точное назначение и обязательный self-check.
Не передавай запуск на исполнителя: он проверяет своё назначение и выполняет работу в уже готовом слоте.
Если назначение не совпало, исправляет оркестратор; исполнитель сообщает причину и не создаёт другой слот.
Сохраняй соответствие «задача → проект → слот/path → ветка → workspace → терминал/алиас → агент».

В файл задания включи:

- цель, ожидаемый результат и необходимые исходные данные;
- путь выделенной копии и требование прочитать её инструкции;
- границы изменений и зависимости от других исполнителей;
- подходящие проверки, полномочия на коммит и внешние действия;
- требование завершить ответом с результатом, файлами, проверками, блокерами и маркером `[[DONE-X]]`.

Не передавай полномочия на push, публикацию, merge или коммит сверх поручения пользователя.
Для параллельных проверок учитывай общие БД, порты и другие внешние ресурсы; отдельный worktree их не изолирует.

Ожидай маркер через `agent sess wait <alias> --marker DONE-X --timeout 45 --json`.
Для follow-up используй anchor из `send`. Код 3 разбирай как вопрос/разрешение, 7 — как возможную
доставку без подтверждения; подробности в agent-sessions. Сообщай пользователю существенные результаты
и блокеры между ожиданиями. Готовность зависимости определяй по проверенному результату, не по названию
терминала или одному маркеру. Прочитай изменения и заявленные проверки перед передачей следующей задачи.

По завершении собери результаты и оставшиеся решения. Коммит — по [agent-commit](../agent-commit/SKILL.md)
и правилам продукта. Закрой завершённые сессии по [agent-cleanup](../agent-cleanup/SKILL.md).
Невлитую ветку не удаляй и не переключай обходными флагами ради уборки.
