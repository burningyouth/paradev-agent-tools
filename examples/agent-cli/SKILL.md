# agent CLI

При старте новой задачи, включая вручную открытую сессию, до правок выполни `paradev-agent status --json`.
Работай в workspace и рабочей копии, где запущена сессия: запуск в main остаётся в main,
запуск в слоте — в этом слоте. Имя workspace main не означает Git-ветку main/master.
Если `slot: null`, не вызывай slot take/create/prepare и не переходи в другой worktree ради начала задачи.
Ветку задачи в текущей копии создавай или продолжай по правилам проекта; проверка status сама ничего не переключает.
Переход в другой workspace — только по поручению пользователя. Занятость или конфликт в текущей копии
сообщи пользователю, не решай их автоматическим переездом.

Для вручную открытого чата Codex подключённый `UserPromptSubmit` проверяет и подготавливает
текущий слот перед стартом задачи. После успешной подготовки проверь назначение через status.
При вопросе хука о слоте дождись решения пользователя. Если хук недоступен и слот ещё не готов,
используй встроенный процесс `agent-slots`. Тип и имя ветки, базу бери из правил проекта
(для SberCRM — `work task-meta <KEY>`). Готовый слот используй без повторной подготовки.
При делегировании слот готовит и исполнителя запускает оркестратор; запущенный исполнитель
проверяет полученное назначение через status. Несовпадение он сообщает оркестратору без переназначения слота.

Если `paradev-agent status --json` в sandbox завершился с `Host service manifest is stale (recorded PID is dead)`,
это ещё не доказывает остановку host: sandbox может запрещать проверку живого PID и доступ к localhost.
Повтори тот же `paradev-agent status --json` вне sandbox через штатную эскалацию инструмента
(`sandbox_permissions: "require_escalated"`, если доступно). Успех означает, что проверку слота
можно продолжить по полученному status. Если эскалация недоступна или ошибка сохраняется,
продолжай только чтение и диагностируй host; до успешного status проект не меняй.
Не запускай `superset start`, не перезапускай приложение и не удаляй manifest только по этой ошибке.

Работай в контексте текущего продуктового проекта. Прочитай его применимые AGENTS.md / CLAUDE.md
и скиллы соответствующей операции. Каталог установки CLI не является рабочим проектом;
его AGENTS.md описывает сам CLI и не заменяет инструкции продукта.

Если рядом с этим файлом есть `references/personal.md`, прочитай его для личных предпочтений
и проектных дополнений. Установщик сохраняет этот файл при обновлении роутера.

Выбери только нужный встроенный процесс:

| Запрос | Тема справки |
| --- | --- |
| Создать, продолжить сессию, отправить задачу, дождаться результата | sessions |
| Взять, создать, подготовить, освободить слот; перенести локальные файлы | slots |
| Разделить работу между исполнителями и собрать результаты | orchestration |
| Коммит по плану, частичные ханки | commit-plan |
| Закрыть законченные сессии, освободить память | cleanup |
| Подключить скиллы, проверить зависимости, исправить установку | setup |

Выполни `paradev-agent --help <тема>`. Для MCP найди имя процесса через `skills_list` и прочитай его через `skill_read`.
Не загружай все процессы заранее. Если команда `paradev-agent` не найдена, используй известный пользователю
путь установки или инструкцию установки пакета; не угадывай путь на чужой машине.

Процесс, проверки, формат коммита и закрытие задачи определяются продуктовым проектом.
Встроенные скиллы объясняют работу с CLI и восполняют отсутствующие инструкции.
При закрытии задачи прочитай agent-cleanup: единая команда `paradev-agent close` закрывает свой chat
и освобождает слот после подтверждённого финального ответа; применение определяется личным правилом.
Если проект явно требует другой способ доступа, сохрани этот выбор; конфликт уточни у пользователя.
Ошибку CLI сообщи с командой и кодом; изменение самого CLI — отдельная задача.

## Режим сессий

`paradev-agent create` по умолчанию запускает Codex chat (`superset sessions`);
терминальный Codex — с `--cli`, Claude — с `--agent claude`.
`--model` и `--mode` передаются в chat; в Superset 2.0.2 явный `--effort` для chat
недоступен (и `model[effort]` отвергается): опусти его для настройки пресета либо используй `--cli`.
Используй алиас, chat session id или terminal id из ответа; `anchor` передавай в `wait --after` как есть.
`resume` сохраняет `kind: chat|cli` из реестра; старые записи остаются терминальными.

При chat resume/send Superset может заменить session id и terminal id: CLI переносит алиас и keep. Используй новые id/anchor из ответа.
